把工作区当天做的事整理成日报。默认统计今天；用户指定日期时用指定日期。全程中文。

## 第 1 步：收集当天提交

1. 找出工作区内所有 git 仓库：`find <工作区> -name ".git" -maxdepth 6`（Windows 下用 Git Bash 路径）。
2. 逐仓执行：`git -C <repo> log --all --since="<date> 00:00" --until="<date+1> 00:00" --pretty="%h %ad %an %s" --date=format:"%H:%M"`。
   - **必须 `--all`**，不能只查当前分支。
   - 输出可能截断，提交多时改用文件落盘再读。
3. 排除规则：
   - 第三方参考仓（如 `southAfrica_v3/` 下的 SouthAfricaSmartLock、drManageSdk）不写入日报。
   - 纯 merge 提交不单独列条目，除非合并本身是当天的主要工作。
4. 若某条提交信息看不清意图，`git show --stat <hash>` 补看改动范围再归纳。

## 第 2 步：补充非提交工作

日报不止 git 提交，还要扫当天的非代码工作：

- 进度文档 `project progress/` 下最新 `*-最新工作计划-*.txt` 中当日分节里记录的工作（联调排查、部署、配置改动等）。
- 会话中做过的分析/排查结论（如日志定位的故障根因）、环境/运维操作（nginx、yml、重启）。

## 第 3 步：按格式输出

严格按下面的版式输出（这是既有日报的标准格式）：

```
日报（YYYY-MM-DD）

一、【模块名A】
1、一条工作一句话
2、一条工作一句话

二、【模块名B】
1、一条工作一句话
```

格式要求（每条都是为了方便用户直接复制到日报系统给领导看）：

- **分组标题用中文大写序号 `一、` `二、` `三、` 前缀 + `【】`**；组内条目用纯文本小序号 `1、` `2、` `3、`（都是字面字符，复制时带得走）；不要用 `-`、`*` 等 Markdown 项目符号。
- **默认不写 commit hash、分支名等技术标识**——领导看不懂也没用，只有用户明确要求时才附。
- **保持精简**：每组 2~4 条，全文控制在 15 条以内；每个条目一句话说清"做了什么+结果"，用业务语言（页面/功能/现象），不要写内部实现细节（字段名、Redis key、类名、错误码、SQL）。
- 组间空一行；组按当天工作重要性排序，主线工作在前，零散修复合并为「【其他页面修复】」之类的组放最后。
- 结尾一行 `遗留：` 列未闭环事项（待部署/待验证/待上游确认），同样用业务语言。
- 写完提醒一句「序号是纯文本，可整体复制」。

## 汇报

直接输出日报正文即可，不要额外解释过程；若当天确实没有提交也没有其他工作，如实说明而不是编造条目。
